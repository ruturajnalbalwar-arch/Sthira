# Sthira Android app

A native Kotlin app (Jetpack Compose + CameraX + MediaPipe Pose Landmarker) for the physiotherapist. It runs the CDC STEADI 30-second chair stand with live counting, the 4-stage balance test and the Timed Up and Go, fully offline.

The web app stays the team's tooling: `/record` and `/label` produce pilot data, and `web/scripts/fit-params.ts` writes `params.json`. The Android build copies the model, `params.json` and `norms.json` from `web/` at build time, so there is only one copy of each.

## Layout

| Module | What |
|---|---|
| `android/engine` | Pure Kotlin port of the counting engine (`web/src/lib/sthira`), CDC norms and the balance/TUG timers. JVM unit tests. |
| `android/app` | Camera, pose overlay, Compose screens, recording export. |
| `shared/golden/chair-stand.golden.json` | Generated by `web/src/lib/sthira/__tests__/golden.test.ts`. The Kotlin engine must reproduce every case. |

After an intentional engine change in TypeScript, regenerate the golden file (`cd web && UPDATE_GOLDEN=1 npx vitest run golden`), then make `./gradlew :engine:test` pass again.

## Build

Toolchain (matches the local Gradle cache): Gradle 8.7, AGP 8.5.0, Kotlin 1.9.22, Compose compiler 1.5.8, compileSdk/targetSdk 34, minSdk 29, JDK 17 or newer. `android/local.properties` (not committed) holds `sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk`.

```bash
cd android
./gradlew :engine:test :app:testDebugUnitTest   # engine parity + app logic
./gradlew :app:assembleDebug                     # app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease                   # R8-shrunk; signed only if the env vars below are set
```

## Release signing

The keystore must live outside the repo and outside OneDrive, and its passwords only in environment variables.

```powershell
keytool -genkeypair -v -keystore C:\keys\sthira.jks -alias sthira -keyalg RSA -keysize 4096 -validity 10000
$env:STHIRA_KEYSTORE = "C:\keys\sthira.jks"; $env:STHIRA_KS_PASS = "<password>"
.\gradlew :app:assembleRelease
```

Back the keystore up offline. Losing it means the app can never be updated in place.

## Security and privacy controls (and how to verify them)

| Control | Where | Verify |
|---|---|---|
| No network at all: `INTERNET` and `ACCESS_NETWORK_STATE` (merged in by a MediaPipe telemetry dependency) are removed | `AndroidManifest.xml` `tools:node="remove"` | `aapt dump permissions app.apk` lists only `CAMERA` (plus the androidx internal `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`) |
| No cloud backup, no device-to-device transfer | `allowBackup=false`, `fullBackupContent=false`, `res/xml/data_extraction_rules.xml` | `aapt dump xmltree app.apk AndroidManifest.xml` shows `allowBackup=0` |
| No cleartext traffic | `usesCleartextTraffic=false` | same dump |
| Screenshots, screen recording and the recents thumbnail blocked | `FLAG_SECURE` in `MainActivity` | try a screenshot on the phone |
| Only the launcher activity is exported | manifest | the only other exported component is androidx `ProfileInstallReceiver`, guarded by the system-only `DUMP` permission |
| Release build not debuggable, shrunk and obfuscated | `isMinifyEnabled`, `proguard-rules.pro` keeps MediaPipe JNI classes | no `debuggable` in the dump; run the release build on a phone, because R8 problems only show at runtime |
| Recordings are app-private | `filesDir/recordings/`; export only through the system save dialog (no storage permission); delete button | — |
| No personal data in logs | no `Log` calls with landmarks or session data | — |
| Adults only, participant codes instead of names | setup form | — |

What this does not protect against: someone holding the unlocked phone, a rooted device, or someone reverse-engineering the APK. No app is unbreachable; these controls remove network leaks, backups, other apps reading the files and screen capture.

Legal context (India): the DPDP Rules were notified on 13 Nov 2025 and their notice and consent duties apply from 13 May 2027; until then the IT (SPDI) Rules 2011 treat health data as sensitive. The physiotherapist or clinic decides why data is processed, so they are the likely data fiduciary. Not legal advice.

## Install on a phone (sideload)

Enable USB debugging on the phone, then:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\release\app-release.apk
```

First-run checklist: airplane mode on (the app must still work), camera permission prompt, skeleton aligned with the person, which delegate started (GPU or CPU), live fps, a screenshot attempt (should be blocked), export of a recording through the save dialog.

## Known gaps

- Video recording is not implemented; the app saves landmark recordings only.
- Not yet run on a real device: GPU/CPU fallback, overlay alignment, real fps, SAF export, TalkBack, dark theme.
- Rotating the phone or leaving the app during a test interrupts the run (it is marked with an issue, as on the web).
- The counter shows "Counter not tuned yet" until `params.json` has fitted values from pilot clips.
